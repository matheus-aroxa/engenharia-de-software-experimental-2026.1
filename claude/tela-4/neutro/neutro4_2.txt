Pergunta 1: Descreva as escolhas visuais da tela (colors, tamanho de elementos, hierarquia visual, layout). Por que você fez essas escolhas?

A página de criação de conta utiliza um gradiente de fundo (roxo/violeta) para se diferenciar visualmente de outras páginas, criando sensação de segurança e exclusividade. O card branco centrado com border-radius 12px e sombra drop-shadow transmite confiança e profissionalismo. A hierarquia visual começa com título "Crie sua Conta" em 32px bold, seguido de subtitle em 14px cinza mais leve em tom. O formulário usa grid layout com form-groups de 20px gap para separação visual clara. Labels em 14px bold preto indicam campos importantes, com asterisco vermelho (
#e74c3c) destacando campos obrigatórios. Os inputs têm 12px padding, background cinza claro (
#f9f9f9) que muda para branco ao focar, border sutil 
#e0e0e0 que vira laranja (
#ff6b35) ao focar com box-shadow suave. A validação em tempo real usa cores: vermelho para erro, verde para sucesso. Campos agrupados em rows (nome/email) usam grid 2-colunas para eficiência de espaço. O checklist de requisitos de senha usa ícones circulares que mudam de cinza para verde conforme requisitos são atendidos. Os checkboxes são grandes (20px) com labels alinhados à esquerda, garantindo acessibilidade. O botão de submit é laranja (
#ff6b35) em 16px bold, 14px padding com hover animation (lift + shadow). Os botões de login social em estilo outline (white background, border 1px, text cinza). O modal de sucesso usa animação slideUp, reforçando feedback positivo.

Pergunta 2: O que aciona a exibição desta tela? Em que momento da jornada do usuário ela aparece?

Esta tela é acionada quando um usuário não autenticado clica em "Criar Conta", "Registre-se" ou link equivalente em qualquer página da Vitrio (home, header, footer, ou ao tentar acessar áreas restringidas). É o primeiro passo do fluxo de onboarding: (1) usuário descobre a loja, (2) decide criar conta para comprar. A página aparece quando o usuário é novo no site e deseja acessar funcionalidades exclusivas como carrinho, favoritos, histórico de pedidos, ou finalizar uma compra. É crítica para conversão pois reduz fricção ao pedir apenas informações essenciais (nome, email, senha) combinadas com dados demográficos (CPF, data nascimento, estado) necessários para faturamento e conformidade legal brasileira. O usuário sai desta página ao completar o registro com sucesso (modal de confirmação) ou ao abandonar e clicar "Já tem conta? Faça login".

Pergunta 3: Descreva todas as interações possíveis que o usuário pode ter com esta tela, incluindo todos os botões, links e formas de sair ou avançar.

O usuário interage com múltiplos elementos. Em cada input de texto (nome, email, telefone, CPF, data), digita dados e recebe validação em tempo real com feedback visual (verde = válido, vermelho = inválido). O campo CPF tem formatação automática enquanto digita (adiciona pontos e hífen). O campo telefone aceita formato (XX) XXXXX-XXXX. O campo data abre date picker. A senha revela checklist de requisitos (8+ chars, maiúscula, minúscula, número, caractere especial) que se auto-preenchem em verde conforme digitado. O campo "Confirmar Senha" valida coincidência com a primeira senha. Os selects (Gênero, Estado) abrem dropdown com múltiplas opções. Os checkboxes para Newsletter (pré-selecionado) e Termos/Privacidade (obrigatório) podem ser clicados para ativar/desativar. Os links "Termos de Uso", "Política de Privacidade" abrem modais ou abas. O botão "Criar Conta" submete o formulário após validação completa (desabilita durante processamento). Os botões sociais "Continuar com Google" e "Continuar com Facebook" redirecionam para OAuth. Na validação bem-sucedida, abre modal de sucesso com botão "Acessar Conta" que redireciona ao dashboard. Se houver erro, modal de erro com "Tentar Novamente" permite correção. No header, logo "Vitrio" redireciona home, link "Já tem conta? Entre aqui" redireciona login. Ao focar qualquer input, border muda para laranja e shadow laranja aparece. Ao sair do foco após preencher, validação ocorre mostrando ✓ ou mensagem de erro. O formulário é responsivo em mobile, reorganizando inputs de 2-colunas para 1-coluna. Todas as validações impedem envio até estar 100% válido. O campo de erro aparece/desaparece dinamicamente baseado em estado do input.
